# Data classification and version-control policy

This policy applies to new work immediately. Legacy experiments can be reviewed
and migrated gradually; no current directory layout change is required.

## 1. Reproducible inputs — keep in Git

Files belong in this class when another researcher needs them to reproduce a run:

- LAMMPS input scripts such as `in.PDMS`, `in.wall`, and `in.*`
- force-field and potential files such as `.tersoff` and `.alloy`
- structure-generation scripts and analysis source code (`.py`, `.m`, shell scripts)
- small configuration and parameter files
- experiment-specific README files describing purpose, commands, dependencies,
  random seeds, and input provenance
- small, indispensable initial structures after explicit size and license review

Rules:

1. Prefer scripts that generate structures over committing many derived structures.
2. Do not use machine-specific absolute paths in committed inputs.
3. A required `.data` file is an exception to the interim ignore rule. Review its
   size and provenance, then add it explicitly with
   `git add -f path/to/required-input.data` and explain it in the commit or README.
4. Files too large for ordinary Git require a separately agreed Git LFS or external
   data-storage policy; LFS is not enabled yet.

## 2. Generated outputs — do not keep in ordinary Git

Files belong in this class when a run can regenerate them:

- full trajectories and dumps (`*.lammpstrj`)
- restart/checkpoint files
- LAMMPS screen and scheduler output
- routine `log.lammps*` files
- intermediate or final structure snapshots generated by `write_data`
- dense time series such as `msd.dat`, force maps, and Green–Kubo profiles
- temporary files, caches, and editor artifacts

These files remain on local or institutional research storage. Git history is not
a backup system for them. Before local cleanup, confirm that irreplaceable data has
another verified copy.

## 3. Key results — keep compact, reviewable forms in Git

Files belong in this class when they support a scientific conclusion or allow a
reviewer to check an analysis without downloading a full trajectory:

- compact CSV tables containing final observables and uncertainty
- small averaged or reduced datasets
- final plots (`.png`, `.svg`, or publication source)
- analysis scripts that regenerate those tables and figures
- a short description of the source run and analysis method

Key results should be derived from raw outputs, not manually copied without
provenance. Prefer descriptive names such as `viscosity_summary.csv` over generic
names such as `avg.txt`. Include units and column definitions in the experiment
README or file header.

## 4. External or archival data — record, but do not commit directly

Use this class for irreplaceable files that are too large for ordinary Git, such as
selected equilibrated structures or trajectories used in a publication. Until a
shared storage service is selected, record at least:

- experiment/run identifier
- original relative path
- storage location
- file size and checksum
- date and responsible researcher
- LAMMPS version and input commit
- whether the file is raw, processed, or replaceable

Do not write credentials, private URLs, or access tokens into the repository.

## Decision checklist

Before adding a new file, ask in order:

1. Is it needed to configure, generate, or analyze the experiment? Keep it in Git.
2. Can it be regenerated from committed inputs? Ignore it as generated output.
3. Is it a compact result needed to support a conclusion? Keep the reduced result
   and its analysis code in Git.
4. Is it irreplaceable but too large for Git? Store it externally and register its
   provenance and checksum.
5. Is its role unclear? Do not add it until the experiment owner classifies it.

## Interim handling of legacy `.data` and `.txt` files

The legacy layout mixes inputs and outputs in the same directories. Therefore:

- `.data` remains ignored by default as a safety measure against multi-GB commits;
  required inputs must be reviewed and force-added explicitly.
- generic `.txt` is no longer ignored. Small summaries become visible to Git and
  should be classified, while known large generated patterns such as `fz_map*`,
  `minp*`, `origin*`, `msd*`, density profiles, and time-series files remain
  ignored.
- generic `avg.txt` files remain ignored because the current copies are generated
  placeholders or unnamed reductions. Rename a reviewed result descriptively before
  adding it, for example `gyration_summary.csv`.
- existing tracked files are not untracked by changing `.gitignore`.
- no historical commit is rewritten by this policy update.

The preferred future state is to place required inputs and generated run outputs in
clearly named locations so exceptions no longer depend on filename conventions.
